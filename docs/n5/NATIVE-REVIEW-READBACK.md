# Native verdict, then Council validation

New `paperclip_runner-experimental` missions use `native-verdict-readback-v1`. The independent reviewer resolves its native card first. Native `accepted`/root `done` is not Council acceptance: publication and dependent Council work require the attributed terminal report, unchanged candidate/mandate/opinions and every admitted run's known usage. Existing historical verdicts are retained under their original protocol.

The final source run attests the candidate (`attest-transmission`, or the final `attest-n3-transmission` bridge when specialists are configured). Council freezes the exact submission, mandate, reviewer, source run and N3 opinions in the existing aggregate. One bounded active packet and a copyable report example are projected into the native task description. The next candidate replaces the active description block; earlier packets/submissions/verdicts remain immutable in the aggregate. This is reviewer context, not another plan store: the plan remains the native revisioned `plan` document.

The reviewer uses `get_task_context`, task history and native document reads. It calls `resolve_review` with `{decision:"accept"}` or `{decision:"reject",reason:"..."}`, then finishes with a JSON-only native summary matching the supplied example. Copy `schema`, `packetHash` and all `subject` fields unchanged. Set `verdict` (`approved` or `changes_requested`), a substantive `rationale`, and `dispositions` covering every material N3 finding. No new UUID, computed hash, Council API or borrowed credential is needed. Specialist opinions advise; this reviewer owns the native verdict and synthesis.

Council reads the actual interaction and `GET /api/heartbeat-runs/:runId` terminal `resultJson.nativeResult.summary`. It verifies exact source/card/decision/reviewer/run, report subject and packet, native/report verdict agreement, and N3 synthesis with existing validators. It settles source, bridge, specialists, reviewer and correction through existing G4 reservations. Only then does it record a GET observation receipt and apply Council acceptance. Missing/malformed/divergent reports, failed/nonterminal runs or unknown costs keep Council unaccepted. Reconciliation never emits the native verdict again. `reconcile-native-n2` is the existing owner recovery/readback command.

## Dedicated lead and owner assistance

The supported profile uses a lead dedicated to this mission with no other queued work. The owner checks this before each final handoff; only the source/bridge run may be active. Timer wakes stay disabled. After any required N3 bridge has started, and before its attestation/finish, the owner uses the public agent PATCH to set `runtimeConfig.heartbeat.enabled=false` and `wakeOnDemand=false` and reads back the policy. Do not disable demand wakes before N3 has admitted its bridge. Council checks this policy before publishing the review packet; it has no agent-update permission or owner credential.

Native rejection returns the root to `todo`, but native wake admission skips the held lead. After exact reviewer/source costs settle, Council consumes the existing single correction and reserves it in the same company/period/envelope. Inspection then asks the owner to restore demand wakes (timer remains false) and call `release-native-correction` with a fresh `commandId` and `expectedVersion`. This command claims one stable wake intent. If ordinary native recovery already started that admitted correction, Council binds/observes the same run; it does not intentionally create a second run. An unknown wake stays unknown, and command replay does not replace its key. The correction uses existing N2 resubmission/round 2 and fresh N3 opinions. A second rejection preserves native evidence and blocks at the existing correction limit; it does not buy another correction.

On Council acceptance the lead is still held. If the publisher is that same lead, the owner restores demand wakes after complete Council validation and calls `reconcile-delivery`. N5 refuses admission before that policy readback, so no publication intent is consumed by a disabled wake. Distinct publishers retain their own policy. Post-publication correction continues to use the existing owner-assisted REST resume and the same PR.

These operator steps are explicit assistance, not autonomous N6 orchestration or a new model run. The plugin does not change host scheduling, agent permissions or native verdict authority. Public native blockers alone are insufficient as a pre-review hold because they also block reviewer admission on the pinned host.

## Qualification boundary

The installed deterministic test supplies model content/usage through the official native backend seam. Reviewer actions go through the actual native tool authority, run JWT and native interaction route; the terminal summary is generated by that reviewer backend before finish, not fabricated during Council readback. Public owner PATCH, reservations, native cards/runs/finalizer/costs/events and installed plugin handlers are real. Legacy N1 prerequisite rows remain fixtures. No provider/model quality, real UI, GitHub write, terminal sandbox readiness or closed-workspace reconstruction is claimed by this proof. Historical evidence remains unchanged.
